# 新媒体团队工作台

> **四个平台，一个后台；把增长从玄学，做成工程。**

新媒体团队工作台，是专为教培机构打造的矩阵增长「作战中台」。它不是又一块数据看板，而是一套把小红书、抖音、直播、私域社群四条增长曲线收进同一个后台的操作系统——用对标监控盯死竞品、用二创工坊批量复制爆款、用话术库与节奏图谱武装主播、用复盘引擎驱动团队周周迭代，再以权限分级与操作日志把总监、经理、专员拉进同一个作战室。从选题到转化，全链路、可度量、能复制。

## 模块一览

### 员工权限体系

- 角色：管理员（admin）/ 运营（operator）/ 实习生（intern）
- 所有模块操作受权限控制，操作写入全局日志
- 日志包含：操作人、时间、模块、动作、详情

## 技术栈

- **React 18 + TypeScript + Vite 5**
- **Tailwind CSS**（深色科技 + 渐变霓虹 + 玻璃拟态）
- **framer-motion**（动效）+ **recharts**（图表）+ **xlsx**（表格解析）
- 数据持久化：LocalStorage（零后端依赖，可离线运行）

## 初始化与数据持久化说明

### 为什么第一次打开 / 刷新后会出现「初始化工作台」？

工作台是**纯前端应用**，所有数据（账号、成员、配置、任务、API Key 等）都保存在当前浏览器的 `localStorage` 里，默认**不连接后端数据库**。

为了让「审批流」不陷入死锁（必须先有人能审批），系统启动时会检查成员名册：

- **名册为空** → 显示「初始化工作台」，由第一个人创建账号并自动成为**总监**。
- **已有成员** → 进入登录页，用账号密码登录。

因此首次使用必须完成一次初始化，这是正常流程，不是 Bug。

### 为什么我创建完账号、刷新后又回到初始化界面？

如果你已经创建了账号，但按 F5 / 重新打开后又回到上图界面，说明 **localStorage 没有被保留下来**。常见原因：

| 场景 | 说明 | 解决办法 |
| --- | --- | --- |
| **无痕/隐私模式** | 无痕窗口关闭即清空站点数据，刷新可能保留但关闭再开一定丢失 | 换到普通浏览器窗口使用 |
| **沙箱/内嵌预览** | 某些在线预览 / iframe 环境每次打开都是独立存储上下文 | 用浏览器直接访问部署后的独立 URL，不要在预览框里使用 |
| **浏览器主动清理** | 设置了「退出时清除 Cookie 和站点数据」或装了清理插件 | 关闭自动清理，或为站点加白名单 |
| **localStorage 被禁用** | 部分企业浏览器/安全策略会禁用本地存储 | 换用标准浏览器（Chrome / Edge / Firefox） |
| **存储配额已满** | 当 localStorage 超过 5~10MB 时后续写入会静默失败 | 导出备份 → 清理不需要的历史数据 → 重新初始化 |

### 怎么保证数据不丢？

1. **常备份**：登录后点击右上角「设置 → 导出全部数据」，会把当前浏览器里的全部 localStorage 下载为 JSON。换电脑或清数据前务必导出。
2. **常恢复**：在新浏览器里用「设置 → 导入数据」把 JSON 写回，即可恢复原账号和全部业务数据。
3. **不要依赖无痕模式**：无痕窗口里的数据不会长期保留。
4. **真正多人协同需要后端**：如果团队要共享同一份数据（而不是每人浏览器各存一份），必须把成员 / 账号 / 任务等数据搬到服务端数据库，并替换当前的浏览器端登录校验。改造要点见 `client/src/utils/authStore.ts` 文件末尾注释。

### 最小验证

打开浏览器开发者工具（F12）→ Application → Local Storage → 当前域名，应该能看到类似 `member_directory_v1`、`auth_credentials_v1`、`auth_session_v1` 等键。如果刷新后这些键全部消失，就说明浏览器环境在清存储，需要从环境侧解决。
